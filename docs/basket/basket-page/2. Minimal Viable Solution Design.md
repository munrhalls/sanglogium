# Technical Solution: Basket Page

## Pre-requirements
- [x] Update CMS product schema and all products to use price_data.unit_amount (cents) instead of displayPrice (dollars)
- [x] Check CMS product schema and all products to have fields: stock, reservedStock 
- [x] Create getBasketProducts.ts with minimal GROQ query for basket page needs

## Data Actors
- Pre-sync basket handler -> PreSyncBasketItems | empty
- CMS fetcher -> CMSProductsData (price_data, stock, reserved stock)
- Parser -> CMSBasketItems (displayPrice, availableStock)
- ComparisonHandler -> [NoDiscrepancyItems, DiscrepancyItems, UnavailableItems] // discrepancy: displayPrice or availableStock changed 
- Sync status manager -> 'idle' | 'syncing' | 'success' | 'failed'
- CheckoutItemsParser -> PureBasketItems(id, quantity)

## View actors
- render PreSyncBasketItems
- render [NoDiscrepancyItems, DiscrepancyItems, UnavailableItems]
- render empty

## Components
- BasketPage
- SyncBanner (top: success/error messages + retry button on failed)
- BasketItemList
- BasketItem (discrepancy: show old→new for changed fields)
- EmptyBasket

## Entities
- client basket
- CMS
- basket client page
- local storage (only hydration/persist on basket modifications - handled 100% by client basket store)

## Data flow
1. Page refresh/mount or navigated to
2. Pre-sync basket handler checks hasHydrated (Zustand persist handles hydration internally)
3. Check basket items:
   - If empty → render empty
   - If not empty → render PreSyncBasketItems → continue data flow
4. CMS fetcher → CMS → CMSProductsData // on failure: sync status 'failed', render error banner with retry button
5. Parser → CMSBasketItems
6. ComparisonHandler → [NoDiscrepancyItems, DiscrepancyItems, UnavailableItems]
7. Sync status: idle → syncing → success/failed -> render banner
8. Render: empty | PreSyncBasketItems | [NoDiscrepancyItems, DiscrepancyItems, UnavailableItems]
9. Render: 
- PreSyncBasketItems only if sync status 'idle' or 'syncing'; render with basket controls; users can use basket controls present on PreSyncBasketItems during that process
- NoDiscrepancyItems - if empty, don't render; else render each item as is with basket controls
- DiscrepancyItems - if empty, don't render; else - render each item with old vs new value comparision per displayPrice/availableStock field and basket controls
- UnavailableItems - if empty, don't render; if not empty - render banner 'Out of stock', render under DiscrepancyItems/NoDiscrepancyItems, render each item with 'X' checkmark 
10. On checkout button click: passes PureBasketItems to checkout handler // checkout flow 100% out of basket page scope
11. On retry button click (when sync status 'failed'): sets sync status to 'syncing', triggers CMS fetcher flow again (step 4)

## Types
```typescript
interface BasketItem {
  productId: string
  quantity: number
  displayPriceAtAdd: number
  availableStockAtAdd: number
}

interface CMSBasketProduct {
  _id: string
  price_data: {
    currency: string
    unit_amount: number
  }
  stock: number
  reservedStock: number
}

interface CMSBasketItem {
  productId: string
  displayPrice: number
  availableStock: number
}

type SyncStatus = 'idle' | 'syncing' | 'success' | 'failed'

interface DiscrepancyItem {
  item: BasketItem
  oldPrice: number
  newPrice: number
  oldStock: number
  newStock: number
}

type NoDiscrepancyItems = BasketItem[]
type DiscrepancyItems = DiscrepancyItem[]
type UnavailableItems = BasketItem[]
```
