# Feature: Payment Slice

## Perspective
User completing payment after shipping selection in checkout flow

## 1. Objective
User sees the Stripe Payment Element, enters payment details, confirms payment, and is redirected to the success page. The payment amount is computed server-side from Sanity CMS product prices and the selected shipping cost.

## 2. Scope Boundaries

### In Scope
- Compute payment amount server-side from Sanity CMS `price_data` and `shippingChoice`
- Create a Stripe PaymentIntent via `stripe.paymentIntents.create()` with the computed amount
- Return `clientSecret` to the client for Payment Element initialization
- Render `PaymentElement` from `@stripe/react-stripe-js` inside an `Elements` provider
- Handle payment confirmation via `stripe.confirmPayment()`
- Handle 3D Secure / SCA authentication (automatic via Payment Element)
- Redirect to success page on confirmed payment
- Receive and verify `payment_intent.succeeded` webhook events
- Create order, finalize stock, and delete reservation in the webhook handler
- Loading and error states for API calls and payment confirmation

### Out Scope
- Address validation (handled by address slice)
- Shipping selection (handled by shipping slice)
- Stripe Checkout Sessions, embedded sessions, or hosted checkout
- Stripe Product/Price object model (no `stripePriceId`, no Stripe PIM)
- Billing address collection (future scope)
- Saved payment methods / returning customers
- Refunds and disputes
- Email receipts

## 3. Definition of Done (DoD)

### Payment Form
- [ ] DoD [1]: I see the Stripe Payment Element rendered on the payment page.
- [ ] DoD [2]: I can enter payment details (card number, expiry, CVC) in the Payment Element.
- [ ] DoD [3]: I see a loading state while the PaymentIntent is being created.
- [ ] DoD [4]: I see an error message if the PaymentIntent cannot be created.
- [ ] DoD [5]: I see an error message displayed by the Payment Element if my card is declined.

### Payment Confirmation
- [ ] DoD [6]: After clicking pay, `stripe.confirmPayment()` is called with the elements instance and a `return_url`.
- [ ] DoD [7]: If 3D Secure / SCA is required, the authentication flow is handled automatically.
- [ ] DoD [8]: On successful payment, I am redirected to the success/return page.

### Server-Side Integrity
- [ ] DoD [9]: The payment amount is computed server-side by summing `product.price_data.unit_amount × quantity` across basket items plus `shippingChoice.amount`.
- [ ] DoD [10]: The PaymentIntent currency is derived from the product `price_data.currency`, not hardcoded.
- [ ] DoD [11]: The API validates currency consistency across all basket items and shipping choice before creating the PaymentIntent.
- [ ] DoD [12]: The `basketReservationId` is stored in PaymentIntent metadata.

### Webhook
- [ ] DoD [13]: The webhook handler verifies the Stripe signature using `STRIPE_WEBHOOK_SECRET`.
- [ ] DoD [14]: On `payment_intent.succeeded`, the webhook creates an order document in Sanity CMS.
- [ ] DoD [15]: On `payment_intent.succeeded`, the webhook finalizes stock (deducts from real stock using reserved quantities) and deletes the reservation document.
- [ ] DoD [16]: Webhook order creation is idempotent (processing the same event twice does not create duplicate orders).
