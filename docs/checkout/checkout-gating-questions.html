    Checkout Gating Questions

    Every question is a binary check on the running checkout at localhost:3000. If every question in a cluster honestly answers yes, no customer and no store owner has a legitimate complaint about that slice.

    Each question names its evidence — exactly how you settle it yes or no. Dimension tags: securityrobustnessvisualtrust

    Source: _project/checkout-gating-questions/ · rubric & slice map in 00-rubric-and-slice-map.md

    The rubric — every question passes all six
    R1BinaryFails if the honest answer is a scale, a "mostly", or "depends".
    R2Evidence-namedFails if it doesn't state how you'd settle it — a live action, a reproduced attack that fails, a visual comparison, a state/dashboard inspection.
    R3BehavioralFails if it asks whether a file/function/token exists, rather than what the user or owner can observe.
    R4Non-leakyFails if you can picture answering "yes" while a specific person is still, concretely, worse off in that slice.
    R5LeanFails if deleting it doesn't weaken the "irrefutably professional" conclusion.
    R6Policy-neutralFails if it assumes a business rule (a price, a quantity cap, a required field) the store owner never stated.
