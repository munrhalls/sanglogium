## Summary

Source shows a partial Next Metadata API adoption: PDP, category, search and 7 static pages have real `generateMetadata`/`metadata`, but the primary funnel is broken at the top.
P0 count: 6 clusters — placeholder root title/description, zero structured data anywhere (no Product/Organization/WebSite/BreadcrumbList JSON-LD), brand pages with no metadata, and four indexable non-production route trees (`dev`, `sandbox`, `design-system-test`, `(test)`) plus `(admin)`.
P1 count: 4 — no `metadataBase` (all relative canonicals resolve wrong), no OG/Twitter on home/category/products/search, no `og:image` strategy at all, sitemap emits `/category/<slug>` URLs for a route that does not exist (`/products/[...slug]` is the real category route) so every category URL in the sitemap 404s and no real category page is listed.
Verdict: not launch-ready for SEO. A professional evaluator would immediately flag "E-commerce store" as the meta description and the total absence of Product rich-result markup on a commerce site.
Biggest gaps: (1) no Product JSON-LD on PDP, (2) placeholder root metadata inherited by home + all brand pages, (3) crawlable dev/test/admin routes with no `noindex` and not disallowed in `robots.ts`.

## P0 — a professional evaluator would visibly wince

### P0-1 Placeholder root title and meta description
- **Where:** `app/(store)/configuration.ts:8-10`
- **What:** `title: "Sang Logium Audio Shop"` (static, no template) and `description: "E-commerce store"`. Home page `app/(store)/page.tsx` exports no metadata, so it inherits both verbatim.
- **User-visible / SEO impact:** The homepage — the single most-linked, highest-authority URL — indexes with the literal snippet "E-commerce store". Share cards and SERP snippets are worthless; brand queries render a generic description.
- **2026 standard:** Unique, human-written `title` (with `title.template` like `%s | Sang Logium`) and a 140–160 char description selling the premium-audio positioning, set on the `(store)` layout and/or a dedicated home `generateMetadata`.
- **Fix direction:** Replace the placeholder description, add `title.default` + `title.template`, and give `(store)/page.tsx` its own home-specific metadata.

### P0-2 Zero structured data on the entire site — no Product JSON-LD on PDP
- **Where:** `app/(store)/product/[slug]/page.tsx` (no `<script type="application/ld+json">`, no JSON-LD helper exists anywhere — grep for `application/ld+json` / `@context` / `BreadcrumbList` returns no source files)
- **What:** PDP renders name, price, brand, availability and images as plain DOM only. No `Product` schema with `offers`/`price`/`priceCurrency`/`availability`, no `AggregateRating`, no `BreadcrumbList`, no `Organization`/`WebSite`+`SearchAction`.
- **User-visible / SEO impact:** No price/availability/review rich results in Google — the single highest-ROI commerce SEO feature. No sitelinks search box. Merchant listings / Shopping surfaces cannot parse the catalogue.
- **2026 standard:** `Product` + `Offer` JSON-LD on every PDP (essentially mandatory for a store), `BreadcrumbList` on PDP + category, `Organization` + `WebSite` with `potentialAction: SearchAction` on the site root.
- **Fix direction:** Add a JSON-LD component rendered from the same product data already fetched in `generateMetadata`; add Organization/WebSite to the `(store)` layout.

### P0-3 Brand pages have no metadata and no real content
- **Where:** `app/(store)/brand/[slug]/page.tsx:1-21`
- **What:** No `generateMetadata` and no `metadata` export → every brand page inherits "Sang Logium Audio Shop" / "E-commerce store". Body is a scaffold: a single `<h1>{Slug} BRAND` on a `bg-gray-100` card with an empty `{}` where content belongs.
- **User-visible / SEO impact:** Every `/brand/*` URL is a near-duplicate thin page with an identical placeholder description and the word "BRAND" in the H1. Duplicate-content / thin-content signals across the whole brand namespace.
- **2026 standard:** Per-brand `generateMetadata` (title `"{Brand} Headphones & Audio | Sang Logium"`, unique description, canonical, OG) and actual product listings; or `noindex` until built.
- **Fix direction:** Add `generateMetadata`, or short-term return `notFound()` / `robots: { index: false }` for brand routes.

### P0-4 Indexable non-production route trees — dev / sandbox / design-system-test / (test)
- **Where:** `app/dev/layout.tsx`, `app/sandbox/layout.tsx`, `app/design-system-test/layout.tsx`, `app/(test)/layout.tsx:3-6`, `app/(test)/streaming-poc/page.tsx`, plus `app/design-system-test/typography/*` and `buttons/*` pages
- **What:** None set `robots: { index: false }`. `(test)/layout.tsx` ships `title: 'Next.js'` / `description: 'Generated by Next.js'`. `robots.ts` only disallows `/studio/`, so `/dev/design-system`, `/sandbox`, `/design-system-test`, `/streaming-poc` are all `allow: "/"` crawlable.
- **User-visible / SEO impact:** Internal tooling and half-built POCs can be indexed and surfaced for brand queries; "Generated by Next.js" is a live indexable snippet. Crawl budget wasted, brand impression damaged.
- **2026 standard:** Non-production routes get `export const metadata = { robots: { index: false, follow: false } }` in their layout AND explicit `disallow` entries in `robots.ts`, and are excluded from `sitemap.ts` (they already are).
- **Fix direction:** Add `noindex` to each non-store layout and extend `robots.ts` `disallow` to `/dev/`, `/sandbox/`, `/design-system-test/`, `/streaming-poc`, `/packer`, `/manager`, `/normalization`, `/normalize-accessories-section`.

### P0-5 Indexable admin routes
- **Where:** `app/(admin)/layout.tsx:20-32` (renders literal text "layout"), `app/(admin)/packer/page.tsx`, `app/(admin)/manager/page.tsx`, `app/(admin)/manager/performance/page.tsx`
- **What:** No `robots` metadata, not in `robots.ts` disallow, not in sitemap. Layout markup is a stub.
- **User-visible / SEO impact:** Internal operations pages (packer queue, manager dashboards) are crawlable and indexable.
- **2026 standard:** `noindex, nofollow` on the admin layout + `robots.ts` disallow + auth gate.
- **Fix direction:** Add `robots: { index: false, follow: false }` to `(admin)/layout.tsx` and disallow `/packer`, `/manager` in `robots.ts`.

### P0-6 `(test)` layout placeholder metadata
- **Where:** `app/(test)/layout.tsx:3-6`
- **What:** `title: 'Next.js'`, `description: 'Generated by Next.js'` — the Next.js starter defaults, live and indexable.
- **User-visible / SEO impact:** As P0-4; called out separately because it is an explicit wrong `metadata` export, not just an omission.
- **2026 standard:** Remove or replace with `noindex`.
- **Fix direction:** Set `robots: { index: false }` and a real internal title.

## P1 — they would note it

### P1-1 No `metadataBase` anywhere
- **Where:** `app/(store)/configuration.ts:4-22` (no `metadataBase`); relative canonicals at `app/(store)/products/page.tsx:96`, `app/(store)/products/[...slug]/page.tsx:136` (`canonicalCategoryPath` returns `/products/...`), `app/(store)/search/page.tsx:52`
- **What:** Relative `alternates.canonical` and relative OG URLs have no base to resolve against; Next falls back to `http://localhost:3000` and logs a build warning.
- **User-visible / SEO impact:** Canonical and `og:url` tags emit `localhost` URLs in production → canonicalization broken on category, all-products, and search; social scrapers get localhost.
- **2026 standard:** `metadataBase: new URL('https://sanglogium.com')` on the `(store)` layout metadata.
- **Fix direction:** Add `metadataBase` to `configuration.ts`.

### P1-2 No OpenGraph or Twitter on home, category, all-products, search
- **Where:** `app/(store)/configuration.ts` (no `openGraph`), `app/(store)/products/[...slug]/page.tsx:133-138`, `app/(store)/products/page.tsx:93-98`, `app/(store)/search/page.tsx:35-56`
- **What:** These templates return only `title` + `description` (+ canonical/robots). No `openGraph`, no `twitter`.
- **User-visible / SEO impact:** Links to the homepage and every category/listing page shared on social or messaging render as bare text with no card, image, or site name.
- **2026 standard:** Every template emits `openGraph` (title, description, url, siteName, type, image) and `twitter` (`summary_large_image`, image). Best done via defaults on the layout that each page extends.
- **Fix direction:** Add a shared `openGraph`/`twitter` block to `configuration.ts` and let per-page metadata override title/description.

### P1-3 No `og:image` strategy at all
- **Where:** entire `app/` tree — no `opengraph-image.*` / `twitter-image.*` files (glob returns nothing), PDP `openGraph` block at `app/(store)/product/[slug]/page.tsx:89-94` has no `images`, static pages `openGraph` at e.g. `app/(store)/about-us/page.tsx:15` have no `images`
- **What:** Not a single OG image is defined anywhere, static or dynamic.
- **User-visible / SEO impact:** Every shared link — including product pages — renders an imageless card. On a premium visual product this is a direct conversion loss.
- **2026 standard:** A default static `opengraph-image` on the store layout plus a dynamic per-PDP OG image (Next `ImageResponse` or the product's Sanity image piped into `openGraph.images`).
- **Fix direction:** Add `app/(store)/opengraph-image.tsx` and set `openGraph.images` from `product.images[0]` in the PDP `generateMetadata`.

### P1-4 Sitemap references a non-existent category route; real category pages absent
- **Where:** `app/sitemap.ts:49-58` emits `${SITE_URL}/category/${slug}`; the actual category route is `app/(store)/products/[...slug]/page.tsx` (URL `/products/<path>`). There is no `/category/[slug]` route in `app/`.
- **What:** Every category URL in the sitemap points to `/category/<slug>`, which 404s. The indexable category pages under `/products/...` are never listed. Brand pages (`/brand/<slug>`) are also absent.
- **User-visible / SEO impact:** Search Console reports sitemap URLs returning 404; category pages rely solely on internal-link discovery; nested category paths (`/products/a/b`) are unreachable via sitemap.
- **2026 standard:** `sitemap.ts` enumerates the canonical URL of every indexable product, category (full path), and brand page, and nothing else.
- **Fix direction:** Change the category loop to emit `canonicalCategoryPath`-style `/products/<full slug path>` and add brand URLs; drop `/basket` and `/checkout` from the static list (see P2-3).

### P1-5 PDP has no canonical
- **Where:** `app/(store)/product/[slug]/page.tsx:85-104` — the returned metadata object has `title`, `description`, `openGraph`, `twitter`, `other`, but no `alternates.canonical`.
- **What:** Product pages emit no canonical link.
- **User-visible / SEO impact:** Any tracking/query-param variant of a product URL (`?ref=`, `?variant=`) is treated as a separate URL; duplicate indexing risk on the most valuable pages.
- **2026 standard:** `alternates: { canonical: '/product/' + slug }` on every PDP.
- **Fix direction:** Add `alternates.canonical` to the PDP metadata return.

### P1-6 No BreadcrumbList structured data despite visual breadcrumbs
- **Where:** `app/(store)/product/[slug]/page.tsx:33-51` (hardcoded `<nav aria-label="Breadcrumb">`), `app/components/ui/breadcrumbs/CategoryBreadcrumbs` (used at `products/[...slug]/page.tsx:90`)
- **What:** Breadcrumbs exist as DOM only; no `BreadcrumbList` JSON-LD.
- **User-visible / SEO impact:** No breadcrumb trail in SERP results; lost SERP real estate and context.
- **2026 standard:** `BreadcrumbList` JSON-LD mirroring the visible trail on PDP and category pages.
- **Fix direction:** Emit `BreadcrumbList` alongside the visual breadcrumb component.

## P2 — polish

### P2-1 PDP OpenGraph `type` is `website`, should be `product`
- **Where:** `app/(store)/product/[slug]/page.tsx:92` (`type: 'website'`)
- **What:** Product pages declare `og:type=website`.
- **Impact:** Some scrapers use `og:type=product` to enable price/availability OG fields.
- **2026 standard:** `openGraph.type: 'product'` with `og:price:amount` / `og:price:currency` (or rely on JSON-LD).
- **Fix direction:** Set `type: 'product'`.

### P2-2 Junk custom meta tag `seo-title`
- **Where:** `app/(store)/product/[slug]/page.tsx:101-103` — `other: { 'seo-title': seoTitle }`
- **What:** Emits `<meta name="seo-title">`, a non-standard tag no engine reads.
- **Impact:** Harmless bloat; signals cargo-culting to a reviewer.
- **2026 standard:** Remove; the real title/OG title already carry this.
- **Fix direction:** Delete the `other` block.

### P2-3 Cart / checkout listed in sitemap
- **Where:** `app/sitemap.ts:64-65` (`/basket`, `/checkout` in `staticRoutes`)
- **What:** Transactional, no-index-worthy pages are advertised to crawlers.
- **Impact:** Wasted crawl; these have no `robots` noindex either.
- **2026 standard:** Exclude cart/checkout/account/auth from sitemap and mark them `noindex`.
- **Fix direction:** Remove from `staticRoutes`; add `robots: { index: false }` to `basket`/`checkout`/`account`/auth pages.

### P2-4 Generic category descriptions
- **Where:** `app/(store)/products/[...slug]/page.tsx:135` — `` `Browse ${metadata.name} headphones and audio equipment` ``
- **What:** Formulaic description; also asserts "headphones" for every category (e.g. a cables category).
- **Impact:** Thin, near-duplicate meta descriptions across categories; occasional factual mismatch.
- **2026 standard:** Use a category description field from Sanity, falling back to a count-aware template.
- **Fix direction:** Pull `metadata.description` from CMS; template only as fallback.

### P2-5 Non-production pages inside `(store)` group
- **Where:** `app/(store)/normalization/page.tsx`, `app/(store)/normalize-accessories-section/page.tsx`
- **What:** Utility pages sit under the store route group, so they inherit the indexable store layout and are crawlable.
- **Impact:** Two more low-value indexable URLs.
- **2026 standard:** Move out of `(store)` or add `noindex` + `robots.ts` disallow.
- **Fix direction:** Add `robots: { index: false }` and disallow.

### P2-6 `(studio)` relies solely on robots.ts, no `noindex`
- **Where:** `app/(studio)/layout.tsx:1-20` (`"use client"`, metadata commented out), `app/robots.ts:8`
- **What:** Studio is disallowed via `robots.ts` only; the layout is a client component so it cannot export `metadata`. No `X-Robots-Tag`.
- **Impact:** If `robots.ts` regresses, Studio becomes indexable; `disallow` does not remove already-indexed URLs.
- **2026 standard:** Belt-and-suspenders `X-Robots-Tag: noindex` header for `/studio/(.*)` in `next.config.ts`.
- **Fix direction:** Add a `headers()` entry for the studio path.
