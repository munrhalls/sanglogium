## P0 — a professional evaluator would visibly wince (fix before showing anyone)

### BL-P0-1 · Storefront prices render in USD `$`, checkout/basket/email in PLN `zł`
`[content]` — `app/components/ui/Price.tsx:12` defaults `currency:'USD'`/`en-US`; called bare by
`ProductCard:71`, `ProductInfo:84`, `IemCard:51`, `AccessoryCard:48`, plus hardcoded `$` in
`featured/card/CardDetails.tsx:42`, `NewestRelease.tsx:95`, `ActiveFilterChips.tsx:47`,
`AutocompleteItem.tsx:45`, `RelatedProducts.tsx:89`. Checkout, order history, receipt emails
all correctly use `pl-PL`/`PLN`. **Same order shown in two currencies.**
→ Fix: one `formatPLN` helper, route every price through it, delete the `en-US` formatters.
Also `Price` `variant='default'` rounds to whole units (`Price.tsx:16`).

### BL-P0-2 · Placeholder root metadata — homepage indexes as "E-commerce store"
`[seo, content]` — `app/(store)/configuration.ts:8-10`: `title:"Sang Logium Audio Shop"`,
`description:"E-commerce store"`. Homepage and every store route without its own metadata
inherit both; brand pages too.
→ Fix: real `title.default` + `title.template "%s | Sang Logium"`, written ~150-char
description (reuse about-us copy), add `metadata` to `(store)/page.tsx`. Copy already drafted
in portfolio repo `SANGLOGIUM-READINESS.md` / beads `portfolio-my6.1`.

### BL-P0-3 · Zero structured data anywhere — no Product JSON-LD on PDP
`[seo]` — grep for `application/ld+json` / `@context` returns nothing. No Product/Offer,
BreadcrumbList, Organization, or WebSite+SearchAction. Highest-ROI commerce SEO feature,
entirely absent.
→ Fix: JSON-LD component from the product data already fetched in `generateMetadata`
(`product/[slug]/page.tsx`); Organization + WebSite on the `(store)` layout; BreadcrumbList
on PDP + category.

### BL-P0-4 · Non-production route trees are crawlable and not noindexed
`[seo]` — `dev/`, `sandbox/`, `design-system-test/`, `(test)/streaming-poc` (`title:"Next.js"`,
`description:"Generated by Next.js"`), `(admin)/packer`+`manager`, `(store)/normalization`,
`(store)/normalize-accessories-section`. `robots.ts:8` only disallows `/studio/`.
→ Fix: `robots:{index:false,follow:false}` on each non-store layout + extend `robots.ts`
disallow list. (`(admin)` also needs an auth gate — see BL-P1 list.)

### BL-P0-5 · Sitemap emits `/category/<slug>` URLs for a route that doesn't exist
`[seo]` — `app/sitemap.ts:49-58`; real category route is `/products/[...slug]`. Every sitemap
category URL 404s; real category pages never listed; brand pages absent; `/basket` + `/checkout`
wrongly included.
→ Fix: emit `/products/<full slug path>`, add brand URLs, drop transactional routes.

### BL-P0-6 · No `not-found.tsx` anywhere — every 404 is Next's unstyled default
`[states]` — `notFound()` called in `product/[slug]/page.tsx:17`, `products/[...slug]/page.tsx:37,69`,
`account/orders/[orderNumber]/page.tsx:62`; no boundary at any level. Stale product links, mistyped
URLs → blank white dead end, no nav/search/footer.
→ Fix: global branded `app/not-found.tsx` (nav + search + category links) and a product-specific
`product/[slug]/not-found.tsx`.

### BL-P0-7 · Payment-failure recovery button links to non-existent `/support`
`[states]` — `checkout/success/page.tsx:90,120` — the "we couldn't verify your payment" and
"Stripe down" screens (card possibly already charged) send the user to `/support`, which 404s
to the unstyled default (BL-P0-6).
→ Fix: point at the existing `mailto:support@sanglogium.com` or `/contact`; surface the
reference code.

### BL-P0-8 · Out-of-stock products can be added to the basket
`[states]` — `ProductInfo.tsx:67` shows "Out of Stock" text but `BasketControls.tsx:60`
`handleAdd` never checks stock; item enters the store, `BasketManager.tsx:100` caps qty to 0 →
broken zero-quantity row; checkout later bounces to `/basket?error=out_of_stock`.
→ Fix: pass `product.stock` into `BasketControls`; disable / swap for "Notify me" when `<= 0`.

### BL-P0-9 · Signed-in account area + all error pages are an un-themed light island
`[visual, content, states]` — `account/**` (dashboard, orders, order detail, addresses,
wishlist) use raw `text-gray-*` / `border-gray-*` / `text-2xl font-bold` on the `bg-brand-900`
body → dim gray text, vanishing borders, off-scale headings. Same for `app/error.tsx`,
`global-error.tsx`, `checkout/error.tsx`, `product/[slug]/error.tsx`, `products/[...slug]/error.tsx`
(`bg-gray-50`, `bg-blue-600` buttons, raw `error.message` shown to users). `Loader.tsx` paints
a full white overlay + blue spinner as the `/basket` Suspense fallback.
→ Fix: migrate `account/**` and the 5 error files to design tokens (`text-text-*`,
`border-border-*`, `type-*`, `btn-*`, `card-base`); suppress `error.message`; use
`BasketSkeleton` as the basket fallback.

### BL-P0-10 · Rebuild the mobile bottom nav (`ActionBar.tsx`) — unusable and inaccessible
`[accessibility, responsive, cross-browser]` — one component, five defects:
(a) icon-only controls have **no accessible name** — labels are `sr-only` AND `hidden`
(`ActionBar.tsx:29-125`); (b) ~20px tap targets (`h-5 w-5`) in a 44px bar; (c) no
`env(safe-area-inset-bottom)` → iOS home indicator overlaps the icons site-wide; (d) it's a
`<div>`, not `<nav aria-label>`; (e) `-webkit-tap-highlight` not suppressed on the `<Link>`s.
→ Fix: `aria-label` per control, `min-h-11 min-w-11`, `pb-[env(safe-area-inset-bottom)]` on the
bar + matching `<main>` spacer, wrap in `<nav>`, widen the tap-highlight selector in `globals.css`.

### BL-P0-11 · Every fixed/sticky bottom bar ignores `env(safe-area-inset-bottom)`
`[responsive, cross-browser]` — `grep env( → nothing`. Affects the mobile nav (BL-P0-10), the
checkout **Pay** button bar (`PaymentForm.client.tsx:276`), and the shipping-step CTA
(`ShippingPageClient.tsx:247` + its `loading.tsx:53`). The single most important button in the
funnel is drawn behind the iOS home indicator.
→ Fix: `padding-bottom: calc(<pad> + env(safe-area-inset-bottom))` on each bar and its scroll
spacer; confirm `viewport-fit=cover` is set.

### BL-P0-12 · Data-fetch waterfalls block first paint (homepage + PDP)
`[performance]` — homepage `page.tsx:21-22` awaits the 14-projection mega-query, then serially
awaits the IEM-gallery query; `<Hero>` (LCP) is a synchronous child of both. PDP
`product/[slug]/page.tsx:14→21→27` does product → related → wishlist strictly in series with no
Suspense; wishlist is independent yet waits.
→ Fix: `Promise.all` the independent queries; put related-products / below-fold sections behind
their own `<Suspense>` (the PLP already does this).

### BL-P0-13 · LCP product image ships blurred, un-blurs on a timed 350ms transition
`[performance]` — `reveal.module.css:20-29` puts `filter:blur(8px)` + 350ms transition on every
grid image including `priority` ones (`ChunkedProductGrid.tsx:42`); cleared by a JS `load`
handler + 2×rAF. LCP is timestamped at the final sharp paint.
→ Fix: when `priority`, render `ProductImage` with no `data-reveal`/`.reveal` so the first row
paints sharp immediately.

### BL-P0-14 · Checkout address form labels are not associated with inputs
`[accessibility, forms]` — `checkout/address/AddressForm.tsx:136-241` and
`account/addresses/AddressesClient.tsx:102-212`: every `<label>` has no `htmlFor`, every
`<input>`/`<select>` has no `id`, no `aria-label` fallback. The highest-stakes form on the
site; the repo's auth forms already do this correctly.
→ Fix: add `id` + `htmlFor` (or wrap input in label) on every address field.

## P1 — a professional evaluator would note it

### Accessibility (from intel-accessibility)
- **BL-P1-a11y-1** No skip link; `<main>` has no `id` (`(store)/layout.tsx:57`). Keyboard users can't bypass the header.

- **BL-P1-a11y-3** Catalogue mega-nav: no `aria-expanded`/`aria-controls`, no Escape, closed panel keeps links in the tab order (`NavbarManager.tsx:56-134`).
- **BL-P1-a11y-4** Contrast failures: `error-700` body text ~2:1 on dark ("Out of Stock", basket errors); `border-secondary` (#4A4948) on control edges ~1.5:1 (sort/filter triggers). Fails 1.4.3 / 1.4.11.

- **BL-P1-a11y-6** Stepper `+` / `−` buttons have no accessible name (`BasketControls.tsx:102`).
- **BL-P1-a11y-7** Form errors not announced / not focused — address, sign-in, basket (`role="alert"` missing; newsletter is the only one that has it).

## Strong points the audits confirmed (do not touch)

- **Design system core** — `tailwind.config.ts` token layer, fluid clamp type scale, `:focus-visible` baked into every `btn-*`/`input-*`, named shadows, consistent radius.
- **Checkout payment-outcome UI** — declined / canceled / processing / verification-failed / Stripe-down / unexpected are each a distinct on-brand screen with a retry path; server-side anti-tamper totals; funnel guards; iron-session; synchronous order creation + webhook fallback; idempotency check. (Only defect: the `/support` link, BL-P0-7.)
- **Search** — loading, empty, and error states all designed and on-brand; full combobox ARIA; debounced with `AbortController`.
- **Static policy/marketing pages** — 7 pages, substantive real content, one consistent voice, unique metadata + canonical + OG each. Production-quality.
- **Auth forms** — correct `htmlFor`/`id`, pending guards, enumeration-safe forgot-password, fresh-session gate on delete/change, `revokeOtherSessions` on password change.
- **Perf foundation** — custom AVIF/WebP Sanity loader, per-chunk Suspense on the PLP, `loading.tsx` on fetching routes, `next/font` swap, `inlineCss:true` chosen deliberately for streaming, CDN preconnect, static/ISR homepage.
- **Cross-browser foundation** — `dvh` app shell, all inputs ≥16px (no iOS focus-zoom), no `backdrop-filter`, styled range/select across engines, both `-webkit-` and Firefox scrollbar treatments.
- **Double-charge / double-submit** — every mutating submit disables on an in-flight flag; Stripe driven by a single PaymentIntent. No risk found.
