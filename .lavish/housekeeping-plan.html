Target-state spec: the "Repository Layout Standard"

This is the end state. The closeout axis writes it verbatim into CLAUDE.md, so it becomes the rule every agent reads. Elite here means enforceable by a grep, not by taste.

1 · Root allowlist

Only tool-mandated config, tool-generated files at their default path, the three entry docs, a tracked .env.example, and a fixed folder list (app features lib sanity-cms tests scripts tools docs data public _project .github .claude .codex .devin .lavish). Anything new needs owner approval.

2 · Where things go

Local tooling in tools/; test config in tests/setup/; scripts in scripts/ (executed one-offs are deleted); docs in docs/ with an index; closed campaigns in _project/archive/.

3 · Never committed

Secrets, logs, backups, caches, virtualenvs, conversation caches, anything .gitignore matches. Check: git ls-files -ci --exclude-standard is empty (one pending exception).

4 · Naming

Docs and scripts kebab-case; no spaces or non-ASCII in tracked paths; XClient.tsx / XServer.tsx pairs; *.spec.ts(x) unit specs with one documented Playwright exception.

5 · Docs honesty

Living docs contain no dead path. A document that may name outdated paths carries a "Point-in-time document" banner. No document exists twice.

Tooling this standard needs: none to adopt. Enforcement is the PR review plus the verification greps in the closeout phase, because the repo bans agent-run lint/build/test. Optional hardening, each needing your go-ahead because it runs tools: a root-allowlist CI check, knip for dead files and exports, a git filter-repo history purge (G9). Not planned.
