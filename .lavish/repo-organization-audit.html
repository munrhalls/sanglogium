What is genuinely elite (keep it)

  • Enforced module boundaries. The rules are lint-enforced in eslint.config.mjs, not just written down: only @/features/x, /server or /actions may be imported, and only actions.ts may touch Sanity.
  • Thin app/ with route groups. (store), (admin), (studio) and (test) separate audiences. Test routes are guarded by NODE_ENV in (test)/checkout-seed.
  • Single data gateway. sanity-cms/lib/{account,homepage,orders,products} is the only GROQ home. The files are small and discoverable.
  • Explicit test lanes and conventions. The unit / live / e2e / integration split is documented, and specs sit next to their owner.
  • Sane depth. 990 files at depth 3, none deeper than 5 levels. The tree is navigable.
  • Secrets hygiene. No .env* file is tracked.

Findings, ranked

HighF1 · One-off migration material ships to production

public/normalize-accessories-images/ holds 200 PNGs (up to 2 MB each) served by every deployment. Only app/(store)/normalize-accessories-section/page.tsx references them. That page and app/(store)/normalization/page.tsx sit in the public storefront route group, and a grep for notFound / NODE_ENV / auth found no guard in either. The same images also exist as 287 candidates/*-normalized.png under sanity-cms/utils/migrations/.

Standard: one-off tooling never lives on the production serving path. Fix: once the migration is done, delete both pages and the public/ folder (git history keeps them), or gate them behind NODE_ENV.

HighF2 · The repo is ~80% non-code, with heavy binaries in git

data/ has 703 product .md files, sanity-cms/utils has 302 PNGs, _project/agent-logs/ has 109 tracked .log files, and sanity/backups/backup_products_latest.json is 6 MB. Binaries and logs bloat clones and diffs, and bury the 395 source files.

Standard: code repo holds code, config and docs. Content, binary artifacts and runtime logs go to the CMS, object storage or a data repo. I did not verify whether data/*.md is still a live input to the catalogue pipeline, so it may belong in a separate data repo rather than being deleted.

HighF3 · The root is a dumping ground

63 entries, 37 of them tracked files. Candidates for relocation: helloworld.txt (just "Hello, World!"), progress.txt (untracked report), playwright.{,checkout.,performance.}config.ts, vitest.integration.{config,setup}.ts, vitest.setup*.ts, eslint-plugin-sang-logium.cjs, schema.json (85 KB generated), sanity.types.ts (generated), skills-lock.json.

Standard: keep at root only what a tool requires there (next.config, tsconfig, sentry.*, instrumentation*, sanity.config/cli, vitest.config, lint/format). Everything else goes in tests/config/, tools/ or config/.

MediumF4 · .gitignore is not trustworthy

  • data/catalogue-index.json is listed in .gitignore yet tracked (ignore does not apply to already-tracked files). It is a generated artifact from scripts/build-catalogue-index.mjs.
  • The line # Deployment backups\nbackups/ contains a literal \n inside a comment, so backups/ is never ignored. sanity/backups/ is therefore tracked.
  • logs/ matches only a folder named logs, so _project/agent-logs/*.log and one features/product-filtering log are tracked.
  • .env.example and .env.template are explicitly ignored, so there is no tracked env contract. A new contributor or CI has no template (a local .env.local.template exists but is itself ignored).
  • A .md.save editor backup and a filename containing № and quote characters are committed under data/headphones/.

MediumF5 · Scripts have three homes; one-offs are permanent

Scripts live in scripts/, sanity-cms/utils/migrations/*/ (dryRun.mjs, PRODUCTION_patchPhased.mjs) and _project/*.sh. Eight executed content edits sit loose in scripts/: update-hero-copy, update-newest-release-*, delete-two-products, verify-deleted-two-products, verify-and-fix-*, and update-homepage-accessories in both .mjs and .ts. PowerShell (dev.ps1, agent-ops/*.ps1) and bash (devctl.sh, commit.sh) are mixed.

Standard: one scripts/ with purpose subfolders (ops/, migrations/, dev/). Delete executed one-offs, since history is the archive.

MediumF6 · Docs sprawl across four homes

docs/ (116), _project/ (181), research/ (10) and .devin/ overlap in purpose. Both _project/lessons.md and _project/AI_LESSONS.md exist. research/ marks five files with an _ARCHIVED_ prefix instead of a folder or deletion. docs/ mixes 10 loose files (including dated audits and devin-*-tasks.md task lists) with 11 subfolders. docs/basket/ uses spaces and numeric prefixes (MAJOR ADR.md, 1. PRD.md) while the rest is kebab-case.

Standard: one docs root (docs/{adr,features,guides,research}) with an index, ADRs as NNNN-title.md, no spaces in filenames, trackers in the tracker.

MediumF7 · Sanity code is split four ways, and utils/ is a junk drawer

Sanity lives in sanity-cms/, root (sanity.config.ts, sanity.cli.ts, sanity.types.ts, schema.json), sanity/backups/ and app/(studio). Having both sanity/ and sanity-cms/ is a naming trap. sanity-cms/utils/ mixes migrations, category JSON, brands.txt and getClient.mjs.

Fix: keep the Studio configs at root if the CLI needs them there; move migrations/ out of utils/ (or delete it after F1) and fold sanity/backups into the F2 decision.

MediumF8 · Agent-tooling sprawl at the root

.claude/ (82 files, 76 of them a vendored vercel-react-best-practices skill), .codex/, .devin/, .lavish/, .codeiumignore, skills-lock.json, plus AGENTS.md and CLAUDE.md. skills-lock.json implies the skills are restorable from the lockfile, so vendoring 76 files duplicates it.

Standard: commit config and rules; do not commit third-party content that a lockfile can restore.

Low–MedF9 · App-layer leaks and duplicates

  • app/(store)/lib/fetchHomepageData.ts (46 lines) puts a lib/ inside routes, against the repo's own "app/ is route-only and thin" rule.
  • Three dev/test route trees: app/design-system-test/ (6 files, a 730-line page), app/dev/design-system/ and app/(test)/. A grep for guards in the first two layouts found none; confirm by reading.
  • Three shipping handlers: app/api/shipping (41 lines), app/api/shipping/rates (269) and app/api/basket/shipping-rates (187). Unverified: I did not read them, but two "rates" endpoints are a duplication smell worth a look.

LowF10 · Naming and rule drift

  • Four .test.ts(x) files (lib/utils/__tests__/{formatting,price}.test.ts, two in tests/e2e/checkout/) break the 39-file .spec convention.
  • Two spellings for client components: AccountActions.client.tsx and PaymentForm.client.tsx versus AddressesClient.tsx and ImageRevealClient.tsx.
  • lib/shipping/packlink-rates.ts is domain code, but the repo's rule says "lib/: cross-cutting infrastructure only". lib/auth.ts sits beside a lib/auth/ folder.
  • Playwright has three configs at root, while tests/ already carries the lane structure.

LowF11 · Bonus: a script points at a route that does not exist

npm run webhook runs stripe listen --forward-to localhost:3000/api/webhook, but the handler is app/api/webhooks/stripe/route.ts. dev:stripe inherits the bug. It is outside folder organization, but it is a clear mismatch. I did not run the script, only compared the paths.

Remediation order (cheapest, highest-yield first)

  1. 1 · Remove migration leftovers (F1). Delete the two one-off pages and public/normalize-accessories-images/. This is the only item with a live production side effect.
  2. 2 · Repair .gitignore and untrack artifacts (F2, F4). Fix the backups/ line, add *.log and _project/agent-logs/, un-ignore and commit an .env.example. Then git rm --cached the catalogue index, logs, .md.save, helloworld.txt and backups.
  3. 3 · Root diet (F3). Move the Playwright and vitest-setup files to tests/config/ and the ESLint plugin to tools/. Each move needs a path update in package.json or the config that references it.
  4. 4 · One scripts home (F5). Delete executed one-offs; subfolder the rest by purpose.
  5. 5 · One docs root (F6). Fold research/ into docs/, merge the two lessons files, kebab-case docs/basket/.
  6. 6 · Naming sweep and verifications (F9, F10, F11). .test → .spec, pick one client suffix, read the three shipping handlers, fix the webhook script path.
Deliberately not recommended. Splitting into a monorepo, moving app/components/ out of app/, or restructuring features/. The current layout is a documented, lint-enforced decision and changing it would be churn with no payoff.
