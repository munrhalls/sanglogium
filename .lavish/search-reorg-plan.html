Search reorganization: features/product-search

Axis slug search-reorg. Baseline main @ 758ec1f5. Organization only. Turn 1 phase files are written at _project/working-memory/search-reorg/turn-1/.

1. Gap scan (verified by reading the code)

G1 Nothing to build on yet. features/, the tsconfig include and the Tailwind glob do not exist on main; filters Turn 1 creates them. Search Turn 1 is hard-gated on that PR being merged (file-existence checks in phase 1.1).
G2 Lint objects clobber each other. A later flat-config object replaces earlier options for the same rule on overlapping files. A second, independent "outsiders may not deep-import" object for search would silently drop the filters regex for every outsider (and the filters rule-2 object would lose the jest paths etc.). Search cannot copy the filters pattern as a second object. Plan: in Turn 3 restructure to ONE shared rule-1 object listing both feature regexes and ONE rule-2 object covering both feature folders, each repeating the three jest paths. It is a single edit of eslint.config.mjs after filters Turn 3 (the other editor of that file) is merged.
G3 searchProducts.ts is mixed and is a 'use server' module. It holds the GROQ + fetch (stays in sanity-cms/lib/products/), the types AutocompleteProduct / SearchProduct / SearchResult, and a large pure pipeline (facets, category counts, price range, comparators, paging) plus the autocomplete rank/slice. Pure parts move to domain/; the types move with them; the file may afterwards export only async functions (a 'use server' rule). Its imports of filters symbols were re-pointed by filters Turns 1 and 3, so it is edited only in search Turn 3.
G4 One client to server-action boundary breaks rule 2. useSearchController (client, in the UI) imports searchProductsAutocomplete from sanity-cms. The feature may not import sanity-cms, and there is no "fetcher takes state" trick for a hook. Recommendation: the hook takes a fetchSuggestions argument; SearchField.tsx (stays in layout, is the composition root) passes the server action. This is the only signature change of the axis; no behaviour change.
G5 searchScoring.ts has module-level side effects. It builds lookup maps from data/catalogue-index.json at import time. It goes into domain/ but is exported ONLY through server.ts, never index.ts, so the catalogue JSON cannot leak into a client bundle through the barrel. Types (RootCategory) may go through index.ts.
G6 Dormant code. lib/catalogue/semanticConfig.ts and semanticMatching.ts have zero importers anywhere (code, scripts, docs). Turn 1 moves them verbatim (config/, domain/) and exports nothing. Whether to delete them is your call, not this axis.
G7 searchLinks.ts mixes static data and helpers. The two constants (CATEGORY_SUGGESTIONS, POPULAR_SEARCHES) are needed by the pure suggestionEntries.ts, so they become config/searchSuggestions.ts; the href/click helpers (React type import) stay UI-side. This avoids a domain to ui dependency. recentSearches.ts (localStorage) also goes to ui/, not domain, because it is browser-only.
G8 Stays out (verified). lib/catalogue/pagination.ts (also used by products Pagination.tsx) and seo.ts (also used by both products pages). searchRobustness.spec.ts stays in store/__tests__/integration: it calls the live Sanity fetcher, and a spec inside the feature would violate rule 2.
G9 Hidden importers. No .mjs/.cjs, script, CI or config file references any search module (grep over the whole tracked tree). Only docs: docs/search-ux.md and live plans get updated in Turn 4; historical _project files are left alone. CLAUDE.md points at docs/search-ux.md (path unchanged), so it needs no edit.
G10 Skeleton is conditional. Search has no proofs or fixtures (no .mjs, no data files), so __tests__/proofs and data are not created (Rule 1c). Skeleton and name product-search hold; no evidence demands a change.
G11 Log file collision. If search PRs append to _project/filters-sorting/logs/agent-steps.log while a filters PR is open, both append to the same tail and conflict. Search uses _project/search/logs/agent-steps.log instead. Revert this in the phase files if you want a single log.
G12 Small notes. MIN_QUERY_LENGTH = 2 is duplicated (controller and fetcher); left alone, not organization. Filters phase checks assert app/hooks/nuqs/ holds useDrawer + useSearchOverlay; search Turn 2 moves useSearchOverlay, so it is gated on filters Turn 2 being merged. Filters Turn 4 is not written yet, so search Turn 4 will be written after it exists.
