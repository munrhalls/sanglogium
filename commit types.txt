Standard Commit Types
Based on common industry standards (like Angular's commit convention), here are the other types you should use:

docs(...): Updates to documentation only (README, JSDoc, internal wiki).

style(...): Changes that do not affect the meaning of the code (white-space, formatting, missing semi-colons, etc.).

refactor(...): A code change that neither fixes a bug nor adds a feature (e.g., cleaning up logic).

perf(...): A code change that improves performance.

test(...): Adding missing tests or correcting existing tests.

build(...): Changes that affect the build system or external dependencies (e.g., npm, gulp, webpack).

ci(...): Changes to CI configuration files and scripts (e.g., GitHub Actions, Travis, CircleCI).

chore(...): Other changes that don't modify src or test files (e.g., updating .gitignore).

revert(...): Reverting a previous commit.
